## Beskrivelse

Ejeren har godkendt arkitektur B (et modulært læringsunivers): adventure-motoren er en selvstændig
spilklient i en iframe på sin egen oprindelse, og Lærligs eksisterende læringsmotor er fortsat
autoritativ for bedømmelse, mastery, progression, XP/coins, svarhistorik og repetition.

Denne beslutning indfører forbindelsen mellem de to: pakken
`adventure-engine/packages/learning-bridge` (`@adventure-engine/learning-bridge`). Den bygger på
F0-designet (`analyse-laerligverse/11-revideret-laeringsbro.md` §4) og ændrer hverken motorens core,
Lærligs frontend, Edge Functions eller databasen.

### Delene

| Fil | Rolle |
|---|---|
| `src/protocol.ts` | Beskedtyper og **streng validering** begge veje: ukendte felter, forkerte typer, ukendte beskedtyper og beskeder over 8 KB afvises. Ingen DOM, ingen timere |
| `src/host.ts` | `BridgeHost`: værtssiden. Den eneste part, der taler med backend (via `TaskService`) |
| `src/client.ts` | `BridgeClient`: spillets side. Handshake, opgaveanmodning, indsendelse af handling, hjælp, ventetilstand, genafsendelse |
| `src/service.ts` | `TaskService`-grænsefladen, som værten bruger mod backend |
| `src/test-service.ts` | `FakeTaskService`: **testadapter, ikke serveren**. Eksporteres kun fra `…/test-service`, ikke fra pakkens indgang |

### Beskeder

| Retning | Besked | Formål |
|---|---|---|
| spil → vært | `hello` | Versionsforhandling, de interaktionstyper verdenen kan tegne, indholds-id |
| vært → spil | `init` | Ny `nonce` pr. spilsession; `openTask` til genoptagelse |
| spil → vært | `task.request` | `objectiveId`, `purpose`, `surface` (`world`/`overlay`), `contextKey` |
| vært → spil | `task.present` | Uigennemsigtigt `instanceToken`, `kind`, whitelistet `stimulus`, `mode`, `hintsAvailable` |
| spil → vært | `task.action` | Den afsluttede handling: `{kind, payload}` |
| spil → vært | `hint.request` | Hjælp hentes via værten, så serveren logger den |
| vært → spil | `hint.show` | Hjælpeteksten |
| vært → spil | `ack` | `received` / `submitting` / `retrying` (ventetilstand) |
| vært → spil | `task.result` | `correct`/`incorrect`/`pending`/`aborted`, feedback, facit efter lukning, `evidence` (kun visning), `retryable` |
| begge | `error` | Eksplicitte fejlkoder |

### Beslutninger

1. **Kun `bridge/2` understøttes.** bridge/1 blev aldrig bygget, så der er ingen N−1. En ukendt version
   får `error{unsupported_protocol}`, og spillet går i tilstanden `unsupported`.
2. **Spillet kan ikke tildele sig noget.** Protokollen har ingen felter for XP, coins, mastery, evidens
   eller "brugt hjælp", og ekstra felter afvises. `evidence` i `task.result` er kun til visning og sættes
   af serveren.
3. **Spillet ser aldrig et instans-id eller et facit før lukning.** Værten udsteder et tilfældigt
   `instanceToken` pr. instans. Et token, værten ikke har udstedt, giver `unknown_task`. Forkert
   interaktionstype giver `kind_mismatch`.
4. **Afsender:** værten accepterer kun beskeder, hvor `event.origin` er den konfigurerede spiloprindelse
   og `event.source` er iframens vindue. Efter handshake skal `nonce` passe. Spillet tjekker det samme
   omvendt. Afviste beskeder får intet svar.
5. **Idempotens på tre niveauer:**
   - Samme `requestId` → værten svarer med sit gemte svar og handler aldrig igen.
   - Samtidige indsendelser til samme instans deler én indsendelse.
   - Én `submission_id` pr. instans og runde. Den genbruges ved alle genforsøg (H5-semantik, D-273).
6. **Det afsluttede svar er endeligt.** Hvis alle genforsøg fejler, får spillet `aborted, retryable`.
   Den ventende indsendelse gemmes i `sessionStorage` og sendes **uændret** igen ved næste forsøg, også
   efter genindlæsning af værtssiden. Intet svar går tabt, og et nyt svar kan ikke snige sig ind efter
   en netværksfejl.
7. **Genoptagelse:** en ny `hello` (genindlæst iframe) giver en ny `nonce`, så beskeder fra den gamle
   session er døde. `init.openTask` bærer serverens åbne instans (én åben pr. elev,
   `idx_one_open_question`).
8. **Interaktionstyper:** `choice`, `short_text` og `order`. `order` findes **ikke** på serveren endnu
   (L6) og kan kun bedømmes af testadapteren.

## Resultater

- `pnpm vitest run packages/learning-bridge`: 36 tests. De dækker:
  - origin, vindue, nonce, manipulerede felter, overstørrelse og ukendte typer;
  - at spillet aldrig får instans-id eller facit før lukning;
  - dubletter, kapløb, tabte svar, transiente fejl, timeout, permanente fejl;
  - genoptagelse efter genindlæsning af spillet og af værtssiden;
  - hjælp, der gør et rigtigt svar til øvelse (LP-5);
  - at æøå bevares i tekstsvar.
- **Begrænsning:** alt er testet mod `FakeTaskService`. Det beviser broen, ikke serveren.

### Trin B (ikke bygget): rigtig adapter mod Lærligs backend

En `TaskService` over de eksisterende Edge Functions kræver ingen ny databasefunktion for `choice` og
`short_text`. Den rammer dog disse kendte huller, som **hver kræver en separat ejerbeslutning**:

| Behov | I dag | Konsekvens |
|---|---|---|
| `objectiveId`, `mode`, `surface` i opgavehentningen | `get-next-question` vælger selv opgaven og kender ingen af dem | Verdenen kan ikke bede om et bestemt fagligt mål |
| `submission_id` / idempotent genafsendelse | H5 er merget, men ikke anvendt (G1 → 190000 → 190100) | Den gamle sti beskytter belønningen (CAS på `answered=false`), men giver ikke præcis genafspilning |
| Hjælp logget af serveren | Findes ikke | Hjælp kan ikke bruges i rigtige `check`-opgaver |
| `order` som opgaveform | Findes ikke (L6) | Kun testadapteren |
| Spillets egen oprindelse | Ingen subdomæne eller CSP `frame-src` | Hostingbeslutning |

Ingen af disse er ændret her.
