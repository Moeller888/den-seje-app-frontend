## Beskrivelse

**Fund (kun læsning, 2026-10-27).**
- **Database:** RLS-politikken `"debug read access"` er `FOR SELECT TO PUBLIC USING (true)`, og anon og
  authenticated har alle tabelrettigheder på `public.avatar_generation_jobs`.
- **Bekræftet API-eksponering:** en anonym forespørgsel med den offentlige publishable key og kun
  tælling (`limit=0`, ingen rækker hentet) gav `206` med `Content-Range: */78`. Alle 78 jobs og alle 40
  kolonner kan altså læses anonymt gennem Data API. Det gælder prompts, storage-stier, provider-id'er og
  fejldetaljer.
- **Ingen elevdata:** aggregerede tællinger, uden at indhold er læst, viser hverken e-mailadresser eller
  bruger-id'er i `initiated_by`, prompts eller `failure_details`. `initiated_by` indeholder 14
  forskellige etiketter.
- **Ingen skriveadgang:** skrivning var ikke mulig, fordi RLS kun har en skrivepolitik for service_role.

**Hvem læser tabellen lovligt:**
- `admin.html` via `js/admin.js` (`loadGenerationJobs`), som super_admin med rollen `authenticated`.
  Siden er derfor afhængig af den åbne politik.
- Edge-funktionen `avatar-generation` og `tools/avatar-batch` via service_role, som er uændret.
- pg_cron via ejeren `postgres`, som ikke er underlagt RLS.

Ingen andre sider, realtime-abonnementer eller views bruger tabellen.

**Ændring** (migration `20261027110000_avatar_generation_jobs_read_scope.sql`):
1. `"debug read access"` fjernes.
2. Ny SELECT-politik `super_admin_read` for `authenticated` med betingelsen
   `(SELECT public.auth_profile_role()) = 'super_admin'`. Den bruger samme hjælpefunktion som
   analytics-views og politikken `"staff read questions"`.
3. anon mister alle tabelrettigheder på `avatar_generation_jobs`.

**Ikke ændret:** `service_role_full_access`, events-tabellen, triggere, funktioner, rækker og
authenticated's tabelrettigheder. Skrivning er fortsat blokeret af RLS.

## Resultater

**PGlite-test** `tests/unit/avatar-generation-jobs-read-scope-migration-run.test.mjs`: 11/11 grønne.
Fixturet er bygget af repoets egne definitioner ordret, og D-227 er anvendt.
- **Før:** anon, elever og lærere læser alle jobs.
- **Efter:** anon afvises med 42501 for både læsning og skrivning. Elever, lærere, brugere uden profil
  og kald uden subjekt ser 0 rækker.
- **Admin:** en super_admin kører `admin.js`' præcise forespørgsel og får alle jobs.
- **Skrivning:** forbliver blokeret som før.
- **service_role:** beholder fuld adgang, herunder `recover_stuck_job_atomic`.
- **Cron:** pg_cron genopretter stadig jobs, der hænger.
- **Isolation og idempotens:** intet andet ændres, og migrationen er idempotent.

**Mutationer:** 5/5 fanget. Testen opdager hver af disse fejl i migrationen:
- `"debug read access"` fjernes ikke;
- politikken har ingen rollebetingelse (`USING (true)`);
- betingelsen tjekker en forkert rolle (`teacher`);
- anon beholder sine tabelrettigheder;
- admin-politikken mangler.

**Migrationsfil SHA-256:** `ba1c2215e81ece575e91126a2fbe536cf22e6b71abce04d49340272b0381ae8f`.

**Ikke bevist:** en rigtig super_admin-session mod produktionen. Efter anvendelsen verificeres det med
samme anonyme tælleforespørgsel (forventet 401 eller 42501) og ved at ejeren åbner admin-siden.
