### Aktivering uden hul
1. **Ejeren opretter rulesettet (B).** Fra dette tidspunkt kræver merge grøn `unit` og grøn `isolated-e2e (run 1)`, og
   den gamle `test` kører stadig på PR'er.
2. **C som PR, derefter merge.** PR'en skal selv opfylde B. Fra merge tager PR'er ikke længere låsen
   `e2e-shared-supabase`.

Der er intet tidspunkt uden obligatorisk E2E på PR'er.

### Hvordan påkrævede checks opfører sig
| Situation | GitHub | Effekt |
|---|---|---|
| `isolated-e2e (run 1)` fejler | failure | Blokerer merge |
| Kørslen annulleres (nyere push til samme PR, `cancel-in-progress`) | Annulleret tæller ikke som bestået | Den gamle SHA blokeres; den nye får sin egen check |
| Checken startes aldrig (skip-markør i head-commit; `plan` fejler, så `run 1` aldrig navngives) | "Expected — waiting" | Blokerer (fail-closed). Løses med et nyt push uden skip-markør |
| Skipped påkrævet check | Tæller som bestået | Kan ikke ske for `isolated-e2e (run 1)`: jobbet har ingen `if:`. Udledt af konfigurationen, ikke observeret |
| Gammel `test` på PR efter C | skipped | Ikke påkrævet, så den har ingen effekt |

### Rollback, normal: beskyttelsen bevares hele tiden
1. **Revert C via en PR, mens rulesettet er aktivt.** Revert-PR'ens egen kørsel bruger den reverterede `playwright.yml`,
   så den gamle `test` kører på den. PR'en opfylder B og merges normalt. Bagefter kører den gamle `test` igen på alle
   PR'er, og den isolerede er stadig påkrævet.
2. **Kun hvis den isolerede check selv skal ud:** ejeren ændrer rulesettet i ét kald, så de påkrævede checks bliver
   `unit` og `test` i stedet for `unit` og `isolated-e2e (run 1)`. Det er sikkert efter trin 1. **Aldrig mens C er
   aktiv**: så får ingen PR `test`, og alle PR'er sidder fast.
3. Rulesettet slås kun fra som sidste skridt, eller slet ikke.

### Nødprocedure: den isolerede E2E er defekt og blokerer revert-PR'en
- **Ejeren selv** merger revert-PR'en med admin-undtagelsen (`gh pr merge <nr> --merge --admin`, fra ejerens egen
  terminal eller GitHub-UI). Det gælder kun den ene PR; rulesettet forbliver aktivt for alle andre, så der opstår ingen
  permanent merge-deadlock.
- Umiddelbart derefter: normal rollback trin 2.
- **Kan ikke udføres af Claude** (verificeret 2026-10-29):
  - `.claude/settings.json` har `gh pr merge *--admin*` på deny-listen for både Bash og PowerShell.
  - Lærlig-guarden afviser `--admin` hårdt (`~/.claude/hooks/laerlig-guard.mjs`) og blokerer skrivende
    GitHub-API-kald.

**Sammenligning med den gamle pipeline:** på begge PR'er kørte den gamle `test` i hurtig tilstand (cirka 10 s, ingen
Playwright). `classify` klassificerede dem som docs- og avatar-tool-ændringer. For disse PR'er tester den isolerede
E2E altså **mere** end den gamle. Der findes endnu ingen PR, hvor begge pipelines har kørt hele suiten, så paritet pr.
PR mangler stadig.

**Konsekvens for B (åben beslutning):** med B bliver `isolated-e2e (run 1)` påkrævet på alle PR'er. En docs-PR, der i
dag er færdig på sekunder, vil så vente cirka 24 min på den isolerede check. Det er ikke en kø mellem PR'er, men en
ny ventetid. Mulighederne er:
1. acceptere det;
2. senere lade den isolerede check melde grønt hurtigt for de samme docs-, unit- og avatar-tool-tilstande, som
   `classify` allerede bruger.

Mulighed 2 er en selvstændig ændring og ikke bygget.

**Tredje observation, #371 `feat/difficulty-scale-migration-b` (kørsel 40834982704, 2026-10-29):** den isolerede
check fejlede i schema-trinnet, før suiten startede:

- **Årsag:** migration B bygger på tabellen fra migration A (`20261020120000_difficulty_scale_a.sql`). A står på
  `NOT_IN_PRODUCTION`, fordi ejerens beslutning om A udestår, og den replayes derfor ikke. B kan altså ikke anvendes oven
  på produktionens nuværende skema. Det er en reel fejl, fanget fail-closed, ikke en D-110-fejl.
- **Den gamle pipeline** anvender aldrig migrationer og kan derfor ikke se fejlen. På `classify` kører den `full`.
- **Løsning hører til #371 og ejeren:** enten anvendes A sammen med B, så A flyttes til `REPO_AHEAD_OF_PRODUCTION` i
  samme PR, ligesom password-help (D-243), eller også omskrives B, så den ikke afhænger af A.
- **Konsekvens for B:** som påkrævet check ville den isolerede E2E have blokeret merge af #371 med rette.

**Status:** observationsgrundlaget er ikke tilstrækkeligt. Kriteriet er de første 5 almindelige PR'er fra mindst 3
